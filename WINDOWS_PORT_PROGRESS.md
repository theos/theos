## Current implementation
- `bin/test-windows-toolchain.ps1` performs real C/C++/ObjC/ObjC++ ARM64/ARM64e Clang object probes when Clang exists, and real `ld64.lld` dylib/link plus optional ldid probe when a validated SDK exists.
- `bin/theos-windows.py macho-check` validates thin and fat ARM64/ARM64e Mach-O headers.
- Windows xcodeproj and master subproject operations avoid Bash via helper-backed branches.
- `common.mk` no longer hard-fails during Windows bootstrap when Bash is absent; helper-backed operations can load, while `THEOS_WINDOWS_REQUIRE_BASH=1` provides explicit strict compatibility mode.
- Removed duplicate nested Windows conditionals introduced during helper migration in `master/rules.mk`; Swift cleanup and build-session paths now have unambiguous Windows/Unix branches.
- Windows object/output hash tags now use the Python helper directly, avoiding parse-time `echo | md5sum | cut` utilities; Unix hashing remains unchanged.
- Windows compile/link recipes in `instance/rules.mk` now route output moves, object-directory creation, architecture staging, and copies through native helper wrappers; WSL-only Linux strip branch remains unchanged.
- Windows bundle Info.plist relocation uses the native move helper; Unix branch remains `mv`.
- Windows xcodeproj staging uses native mkdir/copy-merge helper paths; the Xcode build target itself remains explicitly unsupported on Windows because Xcode is Apple-only.
- Windows master rules now use native helpers for Swift auxiliary/data directory creation and compile_commands replacement; Unix branches remain unchanged.
- Windows IPA packaging no longer requires external `zip`; it uses the Python archive helper and existing staging wrapper.
- Windows Debian packaging no longer requires `dm.pl`/dpkg-deb; it uses the Python ar/tar builder and existing control-file helper.
- Tweak plist staging uses the native copy helper on Windows.
- Corrected native helper directory-copy semantics: default `copy` preserves source basename like `cp`, including file sources copied into existing directories, while `--merge` models rsync-style layout merging. Windows layout staging explicitly uses `--merge`; this fixes tool/library staging, `Payload/Applications`, bundle, framework, and package layout destinations.
- Added `deb-info` artifact inspection; it validates Debian ar members, `debian-binary`, control tar, non-empty data tar, required Package/Version/Architecture metadata, control mode 0644, root:wheel ownership, and unsafe member paths, including strict bounds and duplicate-member rejection. Added `deb-extract` for independent unpacking.
- Native fakeroot backend for Windows (`makefiles/platform/Windows.mk` + `theos-windows.py fakeroot`). Windows has no POSIX ownership database and the Bash `fakeroot.sh` shim cannot run, so `FAKEROOT` now points at the helper, which preserves the `-p`/`-c`/`-r` interface and records staging metadata to `.theos/fakeroot.json`. `common.mk` only falls back to the Bash shim when the platform did not define a backend, so macOS/Linux behaviour is unchanged.
- The Windows Deb builder consumes that manifest and emits explicit POSIX metadata: directories (including empty ones) and symlinks are serialized, files are `root:wheel` (0:0), modes default to 0755 for directories, 0644 for `DEBIAN/control`, 0755 for maintainer scripts, 0755 for installed Mach-O executables/dylibs/bundles and 0644 otherwise, with manifest overrides. Archives are deterministic (mtime 0, sorted order, gzip mtime 0); two clean rebuilds produce byte-identical `.deb` files.
- `codesign` now routes through the helper, which normalizes the target to a native separator path before invoking the signer. This fixes the root cause of the `.unsigned` failure: ldid derives its temporary file from the raw path string, so a make-generated path mixing `\` and `/` became unopenable. Signing is performed by the real signer with no bypass.
- `makefiles/instance/rules.mk` signer dispatch for Windows is otherwise unchanged, and the POSIX branch still sets `CODESIGN_ALLOCATE=`; macOS/Linux signing is untouched.
- Fixed a silent-failure class in the helper: argparse stores a subcommand *alias* in `args.command`, so `elif args.command == "mv"` never matched when the makefiles invoked `move`, and the helper returned 0 without moving anything (this silently discarded the signed dylib). Aliases are now canonicalized centrally, and an unhandled subcommand raises instead of returning success.
- Windows staging tolerates an absent optional `layout/` tree via `cp --ignore-missing`, matching the POSIX `[ -d layout ] && … || true` recipe, instead of failing the package.
- `internal-package` uses a native plist optimizer (`optimize-plists`) on Windows. `bin/convert_xml_plist.sh` is a no-op notice when plutil/plistutil/ply are missing; the helper performs the same XML→binary plist conversion with Python `plistlib` and leaves non-plist files such as `.strings` untouched.
- Converted the vendored `vendor/lib/CydiaSubstrate.framework/CydiaSubstrate.tbd` from TBD v1 YAML (no `!tapi-tbd` tag) to TBD v4, the same schema as this SDK's own stubs. `ld64.lld` rejects v1 with `unhandled file type`, which made every default (MobileSubstrate-generator) tweak fail to link with `undefined symbol: MSHookMessageEx`; the symbol set, install name and versions are unchanged. This removed the need for the fixture's `generator=internal` flag and its `-Wno-unused-but-set-variable` suppression; the fixture `Makefile` is now a stock Theos tweak makefile.
- `test-windows-toolchain.ps1` accepts explicit `-Linker` and `-Ldid` paths for reproducible probes independent of PATH.
- Added `bin/test-windows-e2e.ps1`: when GNU Make, Clang/Clang++, Perl, ld64.lld, ldid, and a validated user SDK exist, it creates a real Logos tweak project (with a filter plist), runs `make clean` and `make package FINALPACKAGE=1`, then verifies the Debian member layout, control metadata, root ownership and modes, ARM64 architecture, and the embedded signature via `tests/windows/verify_package.py`; missing prerequisites produce an explicit exit 2.
- Added `tests/windows/verify_package.py`, an independent verifier that re-parses the ar/tar structures, checks ownership/modes/paths, queries `macho-check`, asserts `ldid -e` succeeds on the packaged dylib and fails on an unsigned control image, and confirms `LC_CODE_SIGNATURE`.
- The tested iOS tweak/deb package graph no longer requires Bash; remaining Bash-syntax recipes (Swift/Xcode/remote install) stay outside that path.
